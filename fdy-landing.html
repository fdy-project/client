E2E

종단간 암호화

데이터는 브라우저를 떠나기 전에 암호화됩니다. 서버에는 암호문만 도달하며, 평문은 전송되지 않습니다.

CLIENT-SIDE ONLY
ZK

영지식 설계

서버는 비밀번호도, 암호화 키도 알지 못합니다. 인증에 사용되는 건 비밀번호에서 유도된 해시값뿐입니다.

ZERO-KNOWLEDGE
STD

검증된 알고리즘

AES-GCM, Argon2id 등 표준 암호화 스펙만 사용합니다. 검증되지 않은 독자적인 알고리즘은 사용하지 않습니다.

PHC WINNER
// 02

암호화 동작 방식

비밀번호 하나에서 두 가지 키를 유도해 문서와 키를 이중으로 보호합니다.

키 역할 서버 인지 여부
DEK
Data Encryption Key
 문서를 직접 암호화하는 키. 브라우저에서 랜덤 생성됨. ✗ 불가
KEK
Key Encryption Key
 DEK를 암호화하는 키. 사용자 비밀번호에서 Argon2id로 유도됨. ✗ 불가
AuthHash
Authentication Hash
 서버 인증 전용. 비밀번호에서 유도되지만 KEK와 분리됨. ✓ 인지
01 · KEY DERIVATION

비밀번호 → 두 개의 키

Argon2id가 비밀번호 하나에서 KEK와 AuthHash를 분리 유도합니다. GPU 병렬 공격에 강한 메모리 집약적 알고리즘.

→
02 · DOUBLE ENCRYPTION

문서 → DEK → KEK

문서는 랜덤 DEK로 암호화되고, DEK는 다시 KEK로 암호화됩니다. 복호화 체인의 시작은 오직 사용자의 비밀번호.

→
03 · SERVER STORAGE

암호문만 서버에

서버에 저장되는 건 암호화된 문서와 암호화된 DEK뿐. DB가 통째로 유출돼도 내용 복호화는 불가능합니다.

// 이중 암호화 흐름 비밀번호 ──[Argon2id]──▶ KEK # 브라우저 안에만 존재 비밀번호 ──[Argon2id]──▶ AuthHash # 서버로 전송되는 유일한 값 문서 ──[DEK 암호화]──▶ 암호화된 문서 → 서버 저장 DEK ──[KEK 암호화]──▶ 암호화된 DEK → 서버 저장
// 03

실제 사용 방법

일반 노트 앱처럼 사용하면 됩니다. 복잡한 암호화는 브라우저가 자동으로 처리합니다.

01

계정 생성 및 비밀번호 설정

비밀번호를 입력하면 브라우저가 자동으로 KEK와 AuthHash를 유도합니다. 비밀번호 자체는 서버에 전달되지 않습니다.

02

워크스페이스 구성

폴더와 문서를 자유롭게 만듭니다. dev, prod 등 원하는 방식으로 분류하고 문서를 생성합니다.

03

문서 작성

일반 노트처럼 작성합니다. 저장하는 순간 AES-GCM으로 자동 암호화되어 서버로 전송됩니다.

04

어디서나 안전하게 접근

로그인하면 브라우저가 KEK를 재유도해 문서를 복호화합니다. 서버는 이 과정을 알 수 없습니다.
